# HoPE 검증 — 채택 가능성 평가 (결론: 현 스택에 채택 불가, 사유 기록)

논문: Dai et al., *HoPE: Hyperbolic Rotary Positional Encoding for Stable
Long-Range Dependency Modeling in LLMs* (arXiv:2509.05218v2)

`hope_pe.py`는 논문 수식(식 5·6·9~12·23~32, 정리 3.2.2)을 구현하고 **학습 없이
순수 수치로** 검증한다. 재현: `.venv/bin/python training/hope/hope_pe.py`

## 실측 결과

| 검증 | 내용 | 결과 |
|---|---|---|
| C1 | 군 성질 `B(a)B(b)=B(a+b)`, `B'(m)=B(-m)`, `B(m)ᵀB'(n)=B(m-n)` | ✅ 오차 ≤4.4e-16 |
| C2 | RoPE 노름 보존(직교) vs HoPE 노름 변화(비직교) | ✅ RoPE [1.0,1.0] / HoPE [0.449, 2.226] |
| C3 | 모듈러스 경계 `B/A ≤ e^θ` (식 31) | ✅ 최대 2.2255 = `e^0.8` **정확히 tight** |
| C4 | 점근 감쇠 `∝ e^{-d(θ'-θ)}`, 제약 `θ' > max θ_i` | ✅ θ'<θ면 발산(1.3e43), θ'=θ면 무감쇠, θ'>θ만 감쇠 |
| C5 | \|어텐션\| 거리 단조 감쇠 (dim=128, 0~4096, 200표본) | ✅ **RoPE 0.500 / HoPE 0.999** |
| C6 | 정리 3.2.2 위치 판별력 (구성적) | ⚠️ RoPE 5/5 · **HoPE 3/5** |

**논문의 중심 주장은 재현된다.** C5에서 RoPE는 단조성 0.500·부호반전 평균 323회로
명확히 진동하고, HoPE는 0.999·0.7회로 단조 감쇠한다. C3의 경계가 정확히 tight한
것도 감쇠계수 `e^{-θ}`(식 32) 설계가 "최대 증폭을 정확히 상쇄"하도록 유도됐음을
확인해 준다.

## 검증 중 잡은 함정 2건 (우리 쪽 오류였음 — 논문 반증 아님)

1. **부호 지표 오류.** 단조성을 부호 있는 점수로 재면 음수 표본이 0으로 수렴할 때
   '증가'로 잡혀 HoPE 단조성이 0.53±0.50(양극단)으로 나온다. 논문 주장은 어텐션
   **크기** 감쇠라 `|score|` 기준이 맞다 → 0.999.
2. **RoPE 구성 부호.** `k = ρ(+rθ)q`로 두면 `qᵀρ((d+r)θ)q`가 되어 argmax가 `d=-r`.
   `k = ρ(-rθ)q`가 옳다. 이 수정 전에는 RoPE도 0/5로 나왔다.

## C6 — 본 검증에서 나온 독자적 비판

정리 3.2.2("임의 거리 r에 피크를 두는 k가 존재")는 **수학적으로 참이나 실용적으로
공허**하다. 논문 부록 8.1은 "k를 키우면 된다"로 스케치하는데, 실제로 풀면 필요한
키 노름이 거리에 **지수적으로** 폭증한다:

```
r=1   RoPE |k|=0.556 ✓    HoPE |k|=4.3e+00 ✓
r=8   RoPE |k|=2.133 ✓    HoPE |k|=9.1e+05 ✓
r=20  RoPE |k|=0.839 ✓    HoPE |k|=1.4e+16 ✗
r=40  RoPE |k|=0.621 ✓    HoPE |k|=4.5e+33 ✗
```

HoPE 단일 청크는 `score(d) = a·e^{-(θ'-θ)d} + b·e^{-(θ'+θ)d}` 이고, d=r에 극대를
두려면 `b = -(α/β)e^{2θr}` 이 필요해 `|k| ∝ e^{2θr}`. r=20·40의 실패는 논문 반증이
아니라 **파국적 상쇄**(float64 유효자리 ~16 초과)다. 실제 학습된 키 노름은 O(1~10)
이므로 **먼 특정 위치를 지목하는 능력은 사실상 소실**된다.

→ **단조 감쇠(C5)와 원거리 위치 판별(C6)은 상충한다.** RoPE는 어느 거리든 `|k|=|q|`
로 지목 가능하다(진동이 그 대가). HoPE는 안정성을 얻고 그 능력을 내준다. 논문은 이
트레이드오프를 명시하지 않는다.

## 우리 스택 채택 가능성 — 불가

| 대상 | 판정 | 사유 |
|---|---|---|
| K-EXAONE-236B (judge·represent) | ❌ | Friendli **API** — 아키텍처 접근 불가 |
| E9 스코어러 / E11 represent | ❌ | EXAONE-4.0-1.2B는 **RoPE로 사전학습**됨. PE 교체는 사전학습 재수행이 필요하고, FFN-only LoRA로는 불가(가중치가 RoPE 기하에 적응돼 있음) |

**설령 가능했어도 우리 병목이 아니다.** HoPE의 이득은 "train short, test long"
길이 외삽인데, E9는 seq4096 학습·~2500토큰 서빙, E11은 seq2048·입력 중앙값 2955자로
외삽 구간이 거의 없다. 이번 3분 최적화의 실제 병목은 judge JSON **출력 절단**(cap
8192→16384로 해결)과 **순차 디코딩**(배치 병렬 2.15배로 해결)이었고, 둘 다 위치
인코딩과 무관하다.

**남기는 이유**: 향후 자체 사전학습을 하게 되면 C1~C6 구현과 위 트레이드오프 분석이
그대로 판단 근거가 된다. 채택 여부를 "안 해봐서 모른다"가 아니라 **실측 근거로**
기각한 기록.
