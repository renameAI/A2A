# A2A 브라우저 (시제품)

배경화면 위에 떠 있는 페이지 카드 + 왼쪽 세로 탭·즐겨찾기·AI 채팅·팀 채널 + 오른쪽 **채팅방** 하나.
AI와의 대화도, 팀 채널도 같은 채팅방 모양이다(옛 A2A 웹앱을 끼워 넣지 않는다).
새 탭은 웹페이지가 아니라 "무엇을 맡길까요?" 작업 시작 화면(최근 작업 카드 포함)이다. 에이전트는 Claude(`claude-opus-5-5`)가
지금 보고 있는 탭에서 읽고·이동하고·누르고·입력한 뒤, 결과를 A2A 채널에 올린다.

## 실행

```bash
# 엔진(8423)과 웹(3200)이 떠 있어야 채팅·채널 게시가 된다 (dev 인증)
cd browser && npm install && npm start      # start = 셸 UI 빌드(vite) + electron
```

셸 UI만 고칠 땐 `npm run build` 후 `npm run dev`(빌드 없이 electron).

`ANTHROPIC_API_KEY`는 환경변수나 `A2A/.env`에서 읽는다. 그 밖의 설정:
`A2A_WEB_URL` `A2A_ENGINE_URL` `A2A_USER`(기본 boram) `A2A_TENANT`(기본 rename) `A2A_START_URL`(첫 탭, 없으면 새 탭 화면)
`A2A_BROWSER_MODEL` `A2A_BROWSER_EFFORT`(기본 medium).

## 채팅 — AI와 팀이 한 방에서

- 방은 두 종류: **AI 채팅**(나 ↔ 내 에이전트)과 **팀 채널**(A2A `/chat/v1`, SSE 실시간).
- 에이전트의 일도 메시지로 흐른다: 접히는 "작업 과정 · N단계", 결과 페이지 카드(열기 · 팀에 공유), 승인 카드.
- **보내는 규칙**(`renderer/src/store.js` `route`)
  - 팀 채널: 기본은 사람에게. `@에이전트`를 태그하면 내 에이전트가 최근 대화를 데이터로 읽고 일한 뒤 답을 그 채널에 올린다.
    **사람도 태그했으면 AI는 답하지 않는다.**
  - AI 채팅: 기본은 에이전트에게. **사람을 태그하면 AI는 답하지 않고**, 메시지(+붙인 결과)를 팀 채널로 보낸다(보낼 채널은 입력창에서 고른다).
  - 내 에이전트는 나만 부릴 수 있다 — 다른 사람이 채널에서 `@에이전트` 해도 내 브라우저는 움직이지 않는다.
- 엔진에는 AI 자동 답장이 없다(서버 쪽 규칙 없음). 위 규칙은 이 클라이언트가 정한다. 멘션은 서버가 알아듣는 `@user_id`로 보낸다.
- 채널 메시지에 마우스를 올려 **AI에게** → 그 메시지를 붙인 새 AI 채팅. 창이 뒤에 있을 때 나를 부른 글·승인 요청은 시스템 알림.
- 에이전트 글은 `🤖`로 시작한다(서버에 봇 계정이 없어서). 셸은 이를 "A2A 에이전트 · ○○의 에이전트"로 그린다.

## 결과 페이지

에이전트는 HTML을 쓰지 않는다. `create_page`로 블록 명세(stats·table·cards·text·callout·list·sources)를 주면
`renderer/page.html`이 **shadcn/ui**(MIT, Radix·Tailwind 기반) 컴포넌트로 그려 새 탭에 연다 — 표 정렬·검색, 마크다운 복사, 인쇄/PDF.
명세는 `agent.js`의 `validPage`가 모양·크기를 검사한 것만 통과한다. 채널에서 부른 작업이면 같은 내용이 마크다운으로 채널에 올라간다.

## 비밀번호 — 로컬 금고

- **암호화:** `userData/vault.bin` 하나를 Electron `safeStorage`(macOS 키체인이 지키는 키)로 통째로 암호화. 암호화를 못 쓰면 **저장하지 않는다**(평문 대체 없음). 파일을 못 풀면 덮어쓰지 않고 잠근다.
- **감지:** 웹 탭마다 별도 격리 월드에 감시 코드를 넣어 로그인 제출을 잡는다. 값은 그 월드 안에만 두고, 시작 때 만든 비밀 신호로 메인이 꺼내 간다(페이지는 흉내 못 냄, 콘솔·로그에 비밀번호가 안 찍힘).
- **채우기:** 사용자가 안내 줄의 "채우기"를 눌렀을 때만, 저장된 주소(origin)와 지금 페이지가 정확히 같을 때만.
- **보기:** 마이페이지에서 Touch ID(안 되면 확인 창)를 거쳐 한 건만, 20초 뒤 다시 가린다.
- **AI는 못 본다:** 에이전트의 페이지 읽기에서 비밀번호 칸 값은 빠지고, 금고·감시 월드는 에이전트 도구와 분리돼 있다.

## 화면

- 배경화면 프리셋 6종(하늘·새벽·초원·모래·밤하늘·흑연) + 내 이미지. 밝기에 따라 글자 톤(밝음/어두움) 자동
- 단축키: ⌘T 새 탭 · ⌘W 닫기 · ⌘L 주소창 · ⌘D 즐겨찾기 · ⌘S 사이드바 · ⌘J AI 채팅 · ⌘K 팀 채널
- `@`로 붙이기: 탭(페이지 내용) · 지난 AI 채팅 결과 · 채널 · 사람 · 에이전트. 사이드바 항목의 `@` 버튼으로도 붙인다.

## 안전 장치

- 셸만 preload를 갖고, 메인은 셸이 보낸 IPC만 받는다(`e.sender` 확인)
- 웹페이지 탭: preload 없음, sandbox·contextIsolation, 권한 요청 기본 거부, 팝업은 새 탭으로, http(s)만
- 페이지 내용은 `<page>` 데이터로만 전달 — 지시로 따르지 않는다(시험: 숨긴 인젝션 무시하고 사용자에게 보고)
- 승인 필요: 제출·전송·결제·삭제로 보이는 클릭, 엔터 제출, 채널 게시. 비밀번호 칸 입력은 거부
- 채널 게시는 🤖 표시를 붙여 사람이 쓴 글과 구분

## 로그인 호환성 (구글·Firebase 팝업)

**기준선:** 실제 크롬(156)에서 MYSCube 구글 로그인을 REA로 기록했다(2026-10-28, 계정 정보는 넣지 않음).
1. 페이지가 `Cross-Origin-Opener-Policy: same-origin-allow-popups`를 보낸다. 자기가 연 팝업과 연결을 유지한다는 뜻이라, 팝업은 꼭 **진짜 창**이어야 한다.
2. 메인 페이지 안에 `…firebaseapp.com/__/auth/iframe`(결과를 받는 통로)이 열린다.
3. `window.open(…, 'width=…')`으로 팝업에 `__/auth/handler`가 뜨고, 302로 `accounts.google.com`으로 간다.
4. 구글 쪽 COOP는 report-only다. 콘솔의 "COOP would block window.closed" 오류는 크롬에서도 나는 경고다.

**우리 앱에서 하는 일**
- `main.js` `popupPolicy`: 크기를 정해 연 창(`disposition: new-window`)은 같은 세션의 진짜 팝업 창으로 연다. `target=_blank` 링크는 새 탭으로 연다.
- 웹 탭의 User-Agent에서 `Electron/…`과 앱 이름을 뺀다(구글의 "앱 속 브라우저" 차단 대비).
- 자체 시험이 기준선과 같은 순서인지 확인한다. 로컬 흉내 페이지(`login-popup`)는 늘 돌고, 실제 MYSCube(`A2A_SELFTEST_MYSCUBE=1`)는 iframe 200 → handler 200 → 구글 200까지 본다.

**한계**
- 맥 패스키(지문·아이클라우드 키체인)는 Electron에서 기본 지원되지 않는다. 구글이 패스키를 물으면 "다른 방법 시도 → 비밀번호"로 넘어가야 한다(서명된 앱과 애플 권한이 필요하다).
- 화면 없는(headless) 자동화 크롬은 사이트의 Cloudflare 보안에 403으로 막힌다. 기준선은 화면이 있는 일반 크롬으로 떴다.

## 일부러 안 한 것

- **크롬 비밀번호 가져오기** — 크롬이 키체인 키로 암호화한 것을 풀어야 한다. 남의 앱 비밀을 꺼내는 일이라 하지 않는다(크롬에서 CSV로 내보내 가져오기는 다음 후보).
- **확장 프로그램** — Electron은 크롬 확장 API 일부만 지원한다. 웹 스토어 설치·업데이트까지는 사실상 못 한다.
- **동기화** — 서버(로그인·암호화 저장)가 먼저 있어야 한다.
- **여러 창·여러 프로필** — 지금 구조는 창 하나 기준이라 큰 구조 변경이 필요하다.
- **자동 업데이트** — 코드 서명·공증 인증서가 있어야 한다.

## 아직 아닌 것

- 키가 데스크톱 앱에 있다 → 운영에선 엔진에 `/browser/agent` 프록시를 두고 키·비용 상한을 서버에서 관리
- dev 인증(X-Dev-User)만 — Supabase 로그인 연동 필요
- 페이지 표현은 DOM 기반 — CDP 접근성 트리로 바꾸면 더 작고 정확(Aside 방식)
- 에이전트가 쓰는 탭을 백그라운드로 돌리기, 대화 기록 저장, 배포 패키징(서명·자동 업데이트)
