# 메리 딜룸 — 투자 의사결정을 업무 지도에 남기고, 투자심사보고서를 하네스로 쓴다

즐겨찾기 **메리**(`a2a://메리`)로 여는 화면 탭이다. 투자 건 하나에 다음이 모인다.
- 자료와 근거
- 논의와 결정
- 가정과 계산
- 보고서

## 무엇이 업무 지도에 남는가 (핵심)

딜룸의 모든 변경은 수집 로그에 `invest.*` 이벤트로 기록된다(`platform: merry`, `task_id: deal-<id>`). `invest/onto.js`가 이 이벤트를 업무 지도의 노드와 관계로 바꾼다. 관계 하나는 주장 튜플 `a = (s, r, o, I, b, m, π, v, c, ζ)` 하나다.

| 이벤트 | 노드 | 관계 |
|---|---|---|
| `invest.deal` | 투자 건 `deal:`, 작업 `task:deal-…` | 사람 —투자 건 등록→ 투자 건 |
| `invest.stage` | 투자 단계 | 투자 건 —단계→ 내부 IR / 임팩트 심의위 / 본투심 … |
| `invest.source` | 원문 `doc:` | 사람 —올림→ 자료 |
| `invest.fact` | 근거 `fact:` (값·쪽·원문 인용) | 근거 —인용→ 자료 |
| `invest.discussion` | 쟁점 `issue:` (질문·쟁점·강점·우려·답·코멘트) | 사람 —제기함→, 답 —답함→ 질문, 쟁점 —근거→ 근거 |
| `invest.decision` | 결정 `decision:` | 사람 —결정함→, —근거→ 근거·쟁점, —해소함→ 쟁점, —대체함→ 이전 결정 |
| `invest.assumptions` | 가정 `pack:` | 사람 —잠금→, —근거→ 근거, —대체함→ 이전 가정 |
| `invest.compute` | 산출물(계산) | 계산 —계산 근거→ 가정 |
| `invest.section` | 산출물(보고서 섹션) | 에이전트 —씀→, 섹션 —근거→ 근거 |

- **결정은 지우지 않는다.** 바꾸면 새 결정이 이전 결정을 `supersedes`한다. 누가, 언제, 무엇을 근거로 바꿨는지가 남는다.
- **업무 유형:** 투자 건의 작업은 업무 유형 **투자 > 투자 심사보고서**에 붙는다(`worktypes.assign`). 그래서 다른 회사의 다음 투자 건에서도 같은 유형의 지난 흐름(결정, 쟁점, 교훈)을 꺼내 쓸 수 있다.

## 메리와 함께 쓰기 (대화창, `invest/copilot.js`)

보고서 종이 옆의 대화창에서 심사역과 주고받으며 쓴다. 한 번에 생성하지 않는다.

1. **첨부** (📎 또는 끌어다 놓기). 메리가 바로 읽고 쪽 번호·원문 인용이 달린 근거를 뽑아, 섹션별 개수를 대화로 알린다.
2. **섹션 고르기 → 브리핑.** 메리가 "이렇게 쓰려고 해요"로 구성을 먼저 보여 준다.
   - 근거로 채울 수 없는 판단은 객관식으로 묻는다(최대 3개).
   - 답이 올 때까지 기다린다.
   - 고른 답은 **결정**으로 기록된다(누가, 무엇을, 왜).
3. **쓰기.** 종이에 실시간으로 쓰인다. 메리의 생각 요약(`thinking.display: summarized`)이 대화창에 흐른다.
4. **검증·채점 결과를 대화로 알린다.** 도구가 찾은 문제만 한 번 고쳐 쓴다. 남은 "근거 없는 문장"은 처리 방법을 심사역에게 묻는다(확인 필요 표시 / 지우기 / 그대로).
5. **종이의 섹션을 누르고 말하면** 그 섹션을 지시대로 고쳐 쓴다. 이어서 "다음 보고서에도 적용할까요?"를 묻고, 그렇다고 하면 섹션 플레이북에 교훈으로 넣는다(사람 수정 = 가장 좋은 바깥 피드백).
6. **섹션을 고르지 않고 물으면** 첨부 PDF를 직접 읽고 출처(근거 id 또는 자료명·쪽)와 함께 답한다.

대화·생각·질문은 `invest.chat`으로 업무 지도에 남는다. 질문 → 답 → 결정은 `invest.discussion`·`invest.decision`으로 이어진다.

## 검산이 잡는 것

`node selftest-invest.js`는 가상의 투자 건(숫자는 모두 지어낸 값)으로 확인한다. 실제 심사보고서로 돌려 보면 손으로 만든 표에서 이런 모순이 실제로 나온다.
- **손익 표 행 불일치:** 매출 − 원가가 표의 매출총이익과 다르다.
- **시나리오 표 가정 불일치:** Min/Avg/Max 중 한 행만 다른 지분·주식수로 계산돼 있다.
- **본문과 표의 PER 밴드 불일치:** 본문의 할인 반영 범위와 표의 적용 PER이 다르다.

## 남은 결정
- 근거 원문(PDF)은 `userData/invest/files`에 평문으로 저장된다. 업무 로그 암호화·보관 기간 결정과 같이 정한다.
- 플레이북 교훈은 지금은 자동으로 쌓인다. 하네스(`harness.js`)의 채택 흐름(사람이 채택)으로 옮길지 정한다.
- 과거 승인 보고서들에서 섹션별 분석 패턴 라이브러리를 만들지 정한다(AnalysisBank 2609.00818). 쌓인 보고서로 섹션 프롬프트를 오프라인 최적화하는 것도 같이 정한다(GEPA 2507.19457).
- merry(AWS)의 기존 보고서 세션을 읽어 올지 정한다. 읽어 온다면 MCP로 붙인다.

## 확인
- `node selftest-invest.js`: 계산·검산, 딜룸 → 업무 지도, 하네스(모델 대역)
- `A2A_SELFTEST_DIR=<폴더> A2A_SELFTEST_ONLY=merry npm run dev`: 화면 확인
  - `A2A_MERRY_PDF=<PDF>`를 주면 실제 Claude로 근거 추출 → 가정 → 섹션 작성·검증·채점까지 돈다.
