# 하네스 개선 — 수집 계층(EVENTS.md)과 잇는 단계

A2A 에이전트는 **모델을 바꾸지 않고, 모델을 둘러싼 하네스를 일한 기록으로 고친다.**
철학은 Google Research의 Harness²(Apache-2.0, 연구용 CLI)에서 가져온다 — 그 코드를 돌리는 게 아니라 구조를 우리 식으로 옮긴다.

- **하네스** = 시스템 프롬프트 · 가드레일 · 메모리 · 스킬 · 도구 안내 · 스크립트 · 서브에이전트 · 플러그인
- **작업 안에서**: Propose(고칠 안) → Probe(같은 일을 다시 돌려 행동 차이를 봄) → Compose(좋은 쪽으로 합침). 정답 라벨이 없어도 된다.
- **작업을 넘어서**: 채택한 하네스와 **근거가 있는 교훈**만 쌓아 다음 개선에 쓴다.

같은 원자료가 두 갈래로 쓰인다. 서로 섞지 않는다.

```
                    ┌─► (가) 지식: 온톨로지 주장 튜플 (s,r,o,I,m 추출 → 독립 라벨 → 검증)   ← MYSCdoc 6-pager
업무 이벤트(L0) ─────┤
 events.js          └─► (나) 하네스: 신호 → 후보 → 재실행 비교 → 교훈 → 채택               ← 이 문서
```

(가)는 "무엇이 사실인가", (나)는 "에이전트가 어떻게 일해야 하는가"다. 승인/거절은 (가)에서 독립 라벨이 아니고(EVENTS.md 원칙 2),
(나)에서는 **행동 신호**로만 쓴다 — 어느 쪽에서도 "참"의 근거가 아니다.

## 단계 (모두 구현 — 2026-10-28)

| 단계 | 하는 일 | 코드 | 
|---|---|---|
| **L0 수집** | 웹·에이전트·승인·채팅·바깥 도구(MCP)를 출처·해시·`derived_from`과 함께 append-only로 | `events.js` · `docs/EVENTS.md` |
| **L0+** | 실행마다 하네스 지문(`agent.instruction`의 `data.harness = {base, edit?, ema?}`), EMA 도구 결과도 원문(`agent.read`, `platform: ema-station`) | `agent.js` `harnessVersion()` · `collect.agentToolResult` |
| **온톨로지** | 로그 → 업무 흐름 노드·관계. 관계 하나 = 주장 튜플 (s,r,o,I,b,m,π,v,c,ζ), m=`recorded` | `ontology.js` |
| **업무 지도** | 옵시디언식 화면 — 탐색(찾기·유형·목록) / 노트(속성·관계 [[링크]]·백링크·원문·주장 튜플) / 그래프(주변·전체). 사이드바 "업무 지도" · ⇧⌘G | `renderer/src/WorkMap.jsx` · `GraphView.jsx`(d3-force) |
| **L1 올리기** | 마이페이지 "업무 기록 올리기": 끔(기본)·신호만·해시까지·원문까지. 엔진이 다시 거르고(본인 것만·해시 재계산), RLS로 본인 것만 보임 | `sync.js` · 엔진 `app/chat/collect.py` · 스키마 v4 `work_events`/`work_blobs` |
| **L2 신호** | 거절 · 도구 실패 · 오류 · 반복 승인(잠금) · 찾지 못함 · **근거 없는 없다**(EMA 등록 기업/기록과 대조) · 다시 시킴 | `harness.js` `signals()` |
| **L3 하네스 = 데이터** | 일하는 방식에 덧붙이는 글·도구 안내·스킬만 버전으로. 안전 규칙은 `agent.js`가 **언제나 맨 끝에** 붙인다 | `harness.js` · `agent.js` `systemPrompt()`/`toolList()` |
| **Propose** | 신호 하나 → Claude가 교훈 + 수정안(JSON). 가드레일을 약하게 하는 글은 코드가 거절 | `propose()` · `validEdit()`/`WEAKENS` |
| **L4 Probe** | 같은 지시를 기준/후보 하네스로 **부작용 없이** 다시 돌린다 — 기록된 원문으로 페이지를 흉내, 누르기·입력·게시는 "했다고 가정", EMA는 읽기만(연결돼 있으면 실제, 아니면 그때 기록) | `probe()` · `agent.js` `execReplay` |
| **L5 Compose** | Claude가 두 행동을 비교해 판정(우세·신호 해결·새 문제) | `probe()` |
| **L6 채택** | 사람이 채택 → 새 버전 → 이후 실행의 `ran_with`가 그 버전으로 이어진다. 되돌리기 가능 | `adopt()`/`reject()`/`rollback()` · 업무 지도 노트의 단추 |
| **업무 유형** | 새 요청을 "어떤 종류의 일"로 분류(Opus). 이 컴퓨터에서 후보를 20개로 좁힌 뒤 Opus가 고르고, 확신이 낮으면 지난 흐름을 객관식으로 묻는다(고른 답 = 분류 라벨). 지도에 `작업 → 업무 유형` | `worktypes.js` · 에이전트 패널 객관식 · 소급 분류 `onto:call backfillTypes`(아직 화면 단추 없음) |
| **꺼내 붙이기** | 시작할 때 같은 업무 유형(회사가 달라도)·같은 기업·비슷한 지시의 지난 기록을 최대 3개·1,200자, `<memory>` 경계 안에. 틀린 것으로 드러난 답은 다시 붙이지 않는다. 지도에 "꺼내 씀" | `recall.js` · 설정 `recall`/`worktype`(기본 켜짐) |
| **실행 모델** | 작업을 시작할 때 모델을 고정(업무 유형에 정한 모델 > 마이페이지 기본, 기본 Opus 5.5). 하네스 지문에 `model`. 업무 유형 노트의 "Sonnet 5.5로 재실행 비교" — 같은 작업을 하네스는 그대로, 모델만 A/B로 다시 돌려 품질 판정 + 토큰·시간·추정 비용. 결과를 보고 "이 유형은 Sonnet 5.5로" | `agent.js` `host.model` · `harness.js` `probeModel()` · `worktypes.setModel()` |

### L2 — 정답 없는 신호 (이미 쌓이는 이벤트에서)

| 신호 | 어디서 | 뜻 |
|---|---|---|
| 거절 | `approval.decision` `approval_status: rejected` | 그 동작(또는 그걸 고른 판단)이 원치 않던 것 |
| 불필요한 승인 | 같은 종류 동작이 반복 승인(예: 검색창 엔터) | 가드레일 문구가 너무 넓다 — **완화는 사람만**(L3 잠금) |
| 다시 시킴 | 같은 작업에 바로 이어진 `agent.instruction` / 새 작업에 같은 지시 | 첫 답이 모자랐다 |
| 사람이 직접 함 | 작업 뒤 같은 탭에서 사람의 `web.*`·채팅 | 에이전트가 못 한 일 |
| 근거 없는 "없다" | 답(`agent.text`)이 "찾지 못했다"인데, 같은 시기 다른 경로(MCP 등)의 원문에 그 대상이 있음 | 도구 선택 실패 — 아래 사례 |
| 실패한 도구 | `agent.tool_call`의 `ok:false` | 도구 안내·스크립트 문제 |
| 대화 밖으로 나감 | 에이전트 답이 채널에 `echo`로 다시 들어옴 | (가)쪽 순환 방지와 같은 신호 |

### L3 — 하네스 구성요소와 지금 코드

| 구성요소 | 지금 | 개선 대상? |
|---|---|---|
| 시스템 프롬프트 | `agent.js` `SYSTEM` | ✅ |
| **가드레일** | `RISKY`, 승인 게이트, 비밀번호 칸 거부, `<page>/<chat>/<result>/<ema>` 경계, 긴 URL 확인 | **❌ 잠금** — 자동 개선이 안전장치를 깎지 못하게. 바꾸려면 사람 리뷰 + 자체 점검 |
| 메모리 | 작업 요약(`store.tasks`), @맥락 | ✅ |
| 스킬 | 없음 | ✅ 새로 — 예: "EMA 기업 찾기 → 메일 초안" |
| 도구 안내 | `TOOLS` 설명, EMA 서버 안내(`ema.instructions()`) | ✅ (EMA 쪽 안내는 EMA 서버 소유) |
| 스크립트 | `page-tools.js` | ✅ 사람 리뷰 |
| 서브에이전트 | 없음 | 나중 |
| 플러그인(미들웨어) | 수집 훅(`collect.*`) | ❌ 수집 계층은 개선 대상이 아니다 |

## 첫 사례 — "샘플톡 대표님께 프로그램 추천 메일"

- 에이전트는 EMA **화면**에서 "샘플톡"를 찾다가 "없다"고 답했다(스타트업 레지스트리 0곳으로 보임).
- 같은 날 EMA **도구**(`ema_registry_search "톡톡"`)로는 바로 나온다: FRN `HCR-KR-00-003`, 대표 이대표.
- 신호: **근거 없는 "없다"**. 교훈 후보: "EMA 등록 기업은 화면 검색보다 `ema__ema_registry_search`를 먼저."
- Probe: 같은 지시를 EMA 도구가 붙은 하네스로 다시 돌려(L4) 도구 선택이 바뀌는지 본다. 화면은 블롭으로, EMA는 가짜 서버나 읽기 전용 실제 서버로.
- 연락처는 EMA 도구가 AI에게 보여 주지 않는다 — "받는 주소는 사람이 넣는다"는 그대로 맞는 행동이다(교훈으로 바꾸지 않는다).

## 결정이 필요한 것 (L1)

1. **무엇을 올리나**: (a) 신호만(도구 이름·승인/거절·지문, 원문 없음) / (b) + 원문 해시 / (c) + 마스킹한 원문 블롭. Probe(L4)를 서버에서 하려면 (c)가 필요하다.
2. **누가 채택하나**: 교훈·하네스 채택 권한(워크스페이스 관리자?).
3. **개인 동의·삭제**: 직원별 끄기, 지우기 요청(로그는 append-only — EVENTS.md "남은 결정"과 같은 문제).

## 첫 실측 (2026-10-28, 실제 Claude)

샘플톡 사례를 재현해 돌렸다(`A2A_SELFTEST_ONLY=onto A2A_SELFTEST_AGENT=1`).
- 신호 "근거 없는 없다"가 EMA 등록 기업 `HCR-KR-00-003`와 대조돼 잡혔다.
- Claude 교훈: "회사 정보는 화면 검색보다 EMA 도구에서 먼저, EMA를 조회하지 않았다면 '없다'고 하지 않는다."
- 재실행 비교: 기준·후보 **둘 다** `ema__ema_registry_search`로 바로 찾음 → 판정 **비슷함(신호는 해결)**.
  즉 이 실패의 진짜 원인은 프롬프트가 아니라 **도구가 없었던 것**이었다(그래서 EMA 도구 연결이 먼저였다). 이런 판단을 채택 전에 보여 주는 게 이 단계의 목적이다.

## 확인

- `A2A_SELFTEST_DIR=<폴더> A2A_SELFTEST_ONLY=ema npm run dev` — EMA 연결(시험 서버)·도구 결과가 `agent.read`(ema-station)로 남는지·쓰기 승인·재연결·끊기
- `A2A_SELFTEST_DIR=<폴더> A2A_SELFTEST_ONLY=onto npm run dev` — 온톨로지·신호·잠금·채택·계보·업무 지도 화면·되돌리기·올리기(엔진이 떠 있으면)
- 위에 `A2A_SELFTEST_AGENT=1`을 더하면 Claude로 교훈 제안 + 재실행 비교까지(유료)
- 엔진: `CHAT_TEST_PG_A=… CHAT_TEST_PG_B=… .venv/bin/python -m pytest tests/test_chat_platform.py -k TestCollect`
