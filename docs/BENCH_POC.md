# B3 — PoC readiness 벤치마크

`innovation_receptivity` 축의 3태 보정과, purpose(revenue|poc)가 업종 제안을
실제로 가르는지의 발산 측정. 골든셋 `app/eval/poc_golden.json`, 러너
`scripts/run_poc_bench.py`.

```bash
LLM_PROVIDER=openai python scripts/run_poc_bench.py --k 3
```

## 왜 이 축을 재는가

PoC 파트너 찾기는 매출 리드와 판정 축이 다르다 — "살 여력이 있나"가 아니라
"같이 실험할 구조가 있나"다. 이 축의 트랩은 수사(rhetoric)다: "혁신을 핵심
가치로" 같은 말은 협업 구조의 증거가 아니고, 이걸 구조로 승격시키면 PoC 모드는
혁신이라는 단어를 쓰는 회사 목록이 된다.

## 방법론 근거

| 근거 | 가져온 것 |
|---|---|
| ITONICS Startup Readiness Framework | readiness는 기술이 아니라 **구조**(거버넌스·이해관계자 정렬·파트너십 아키텍처)의 문제 |
| IBM EEIMM (Ecosystem-Enabled Innovation Maturity Model) | 오픈이노베이션 성공의 관리 역량 4축 중 ecosystem capability — 실증사업·CVC·액셀러레이터·협업 이력이 그 관측 가능한 증거 |
| [2507.16199](https://arxiv.org/html/2507.16199) | 3태 보정 프로토콜(B2와 동일): 과잉단정/과잉회피 분리 측정 |

## 골든셋 설계 (10케이스)

- stated 5: 공기업 실증 공모, 기업 액셀러레이터(ja), 반복 협업 실적(공식
  프로그램 없이 — 실적도 구조의 증거), CVC+파일럿(en), 공공 실증 지원사업
- absent 5: 생산 규모만, **혁신 수사 트랩**(P05 — 회사명부터 '이노베이트'),
  하청 관계(수직 거래 ≠ 실험 협업), 점포 수 서술, 빈 자료

## 발산 측정

같은 요청자(귤메달·일본)로 purpose만 바꿔 업종 제안을 두 번 받아 라벨 토큰
Jaccard를 잰다. **0.3 미만**이어야 통과 — 목적이 달라졌는데 같은 업종이 나오면
purpose 배선은 장식이다.

## 결과 (GPT-5.6 Luna, k=3)

| 지표 | 값 |
|---|---|
| receptivity 3태 정확도 | **1.000 / 1.000 / 1.000** (k=3) |
| 과잉단정 / 과잉회피 / 값 오답 | 0 / 0 / 0 |
| 업종 제안 발산 Jaccard | **0.132** (통과, <0.3) |

발산의 질적 확인 — revenue: 수입유통사·소매 상품본부·외식 체인·호텔 조달·
기업 선물 조달 vs poc: 대기업 개방형 혁신 부서·지자체 실증사업·유통사 테스트
매장 조직·관광시설 운영사·단체급식. 겹치는 것은 호텔·급식 계열뿐인데 접근
조직이 다르다(조달업체 vs 운영사).

첫 판에 만점이 나온 이유 — B1·B2에서 만든 경계·3태 규율(빈 배열이 정직,
unknown은 값 없음)이 프롬프트에 이미 누적돼 있었다. 새 축이 그 규율을
물려받았다는 것이 이 벤치의 실질 결과다.
