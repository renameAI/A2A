# 2. 프로젝트 핵심 기술

## 2.1 핵심 기술

◦단순 키워드 유사도가 아닌 실제 액셀러레이터의 암묵지를 에이전트가 추론하여 사업 파트너를 발굴하는 A2A 기반 B2B 매칭 시스템을 제안함. 실측에서 검색 top1 정확도 0.960, 원문 대조 환각 0건, 전체 파이프라인 관통(프로필 분석 88.9초·후보 발굴 9.8초·적합도 판단 154.7초, 판단은 표본 1회 조건)을 확인함

### - 핵심 아이디어-Represent ① : 상호보완적 기업 탐색

기존 Graph-RAG 혹은 Agentic-RAG 등 검색 증강 생성(Retrieval-Augmented Generation, RAG) 시스템을 내부 지식 기반의 키워드 검색으로 운영할 경우, 사업 파트너가 아닌 유사 기업을 반환하는 한계를 지님. 기업을 임베딩하여 최근접 이웃을 탐색하면 나오는 것은 파트너가 아니라 경쟁사임. 이에 본 시스템은 자사 기업의 상(像)을 먼저 정의하여 unknown-unknown 상태를 해소하고, 상대 기업의 니즈를 에이전트가 한 문장으로 합성한 뒤 그 문장을 검색어로 사용하는 구조를 채택함. 검색이 향하는 면도 방향에 따라 전환됨 — 판매 요청이면 후보의 '겪는 문제' 면을, 구매 요청이면 후보의 '솔루션' 면을 향해 검색하므로, 동일 기업이 방향에 따라 경쟁사도 되고 공급사도 되는 구조를 명시적으로 반영함

이 원리는 코드 수준에서 집행됨. 판매 방향에서 요청 기업과 동일 산업이거나 솔루션 문면의 중첩도가 0.35를 초과하는 후보는 구매자가 아닌 경쟁사로 분류하여 점수에 ×0.2 강등을 적용함. 실측에서 이 강등을 제거할 경우 상위권이 경쟁사로 채워지는 현상을 확인하였으며, 골든셋의 '동종 경쟁사 배제' 케이스로 회귀 검증을 수행 중임

### - 핵심 아이디어-Judge ② : 판정은 모델, 최종 결정은 사람

판단을 대규모 언어 모델(Large Language Model, LLM)의 단일 호출에 위임할 경우 결정 라벨이 특정 값으로 편중되는 현상이 발생함. 실측에서 K-EXAONE은 축별 판정은 충실히 수행하나 최종 결정 라벨이 conditional로 6건 중 5건 편중됨을 관측하였음. 이에 10개 축의 상태만 모델이 산출하고, 축 상태로부터 결정을 유도하는 것은 우선순위 6단계의 결정론적 규칙이 담당하는 구조를 채택함. 시스템은 후보 순위와 근거만 제시하고 최종 선택은 항상 사람이 수행함

| 순위 | 조건 | 결정 |
|---|---|---|
| 1 | 착취 의도 감지 | **관계 차단** — 가치 훼손으로 판단하여 관계 자체를 종료 |
| 2 | 실행 게이트 결격 | **구조적 종료** — 구조 미달이나 관계는 보존 |
| 3 | 부적합 축 2개 이상 | **구조적 종료** — 복수 축 미충족 |
| 4 | 미검증 축 3개 이상 | **판단 유보** — 검증 불가 항목 다수 |
| 5 | 주의·미검증 1개 이상 | **조건부 진행** — 조건·검증 잔여 |
| 6 | 그 외 | **진행 권고** |

본 구조의 효과는 두 가지임. 첫째, 모델을 교체하여도 결정 정책이 코드에 보존되므로 소버린 AI 환경에서 모델 선택지가 변경되어도 서비스 일관성이 유지됨. 둘째, 판단 국면에 따라 규칙만 교체하면 되므로 유연함 — 실제로 웹에서 갓 발굴한 후보는 프로필이 이름·국가·한 줄 요약뿐이라 10축 중 8~10개가 필연적으로 미검증이 되고, 미검증 3개 이상 규칙을 그대로 적용하면 모든 후보가 판단 유보로 수렴하여 변별력이 0이 되는 현상을 실측함. 이에 탐색 국면에서는 미검증을 감점이 아닌 확인 목록으로 취급하고 가설 부합 축(BB1)만으로 판정하도록 규칙을 분기하였으며, 이 분기 역시 프롬프트가 아닌 코드에 있음

### - 핵심 아이디어-신뢰성 ③ : 정보 부재와 부정의 분리

판정(verdict: 적합/주의/부적합/해당없음)과 검증상태(status: 확인됨/추정/미검증)를 독립 필드로 분리하여 관리함. 자료가 부재하여 판단할 수 없는 경우와 자료가 성립을 부정하는 경우는 상이한 사건이며, 이를 단일 축으로 통합하면 접촉 전 후보가 전부 탈락하는 문제가 발생함. 이에 루브릭에 "정보가 반대하는 경우에만 부적합을 부여한다"를 명문화하여 정보 부재가 부정 판정으로 오분류되지 않도록 설계함. 같은 원리가 검색 단계에도 적용됨 — 산업 정보가 미상인 후보 간 관계는 '동일'이 아니라 '판단 불가'로 처리하여, 미상끼리 상호 인접 판정을 받아 풀 전체가 가산되던 결함을 차단함

## 2.2 기술 구현 방안

핵심 추론에는 K-EXAONE-236B(LG AI연구원, Friendli 전용 엔드포인트)를 사용함. controllable reasoning 기능을 활용하여 "깊은 추론(자유 서술) → 구조화(스키마 강제)"의 2단계 호출 구조를 채택함. 1단계는 전문가 분석문을 자유 서술로 생성하고, 2단계는 그 분석문을 JSON 스키마로 변환만 수행함 — 2단계 프롬프트에 "분석에 없는 내용을 새로 지어내지 말고, 있는 내용을 빠뜨리지도 마라"를 명시하여 추론과 형식화의 역할을 분리함. 이 분리로 스키마 준수율과 환각(hallucination) 억제가 동시에 개선되며, 특히 경량 모델일수록 효과가 크다는 점을 확인하였음

추론 예산은 16,384토큰을 표준으로 설정함. 예산을 4,500토큰으로 축소한 실험에서 추론이 중단되어 폴백 경로로 전환되고 10축 중 8축이 얕은 판정에 머무는 품질 저하를 실측하였으며, 예산 축소는 시간이 아니라 품질을 훼손하는 선택임을 확인하고 표준값으로 명문화함. 반대로 자료가 사실·수치로 조밀한 경우 모델이 층마다 인용을 모두 포함하려다 추론 예산을 소진하고 절단되는 사고도 실측하여, 프롬프트에 "층마다 4~5문장 이내, 사실이 많을수록 대표성 있는 것만 골라 압축"하는 편집 규율을 명시함 — 예산 상한을 올리는 것으로는 해결되지 않는 문제였음(자료가 많을수록 그만큼 길어지는 구조이므로)

보완 스코어러로 EXAONE 1.2B 미세 조정(fine-tuning, 이하 파인튜닝) 모델(E9)을 후보 재랭킹 전용으로 운용함. 학습 코퍼스는 기업 리서치 1,000사로부터 관련도 쌍 5,000건을 생성하였으며, FFN-only LoRA·시퀀스 길이 4096·3 epoch 구성으로 학습함. 로컬 서빙으로 ms 단위 응답이 가능하여 대형 모델 호출 없이 순위 품질을 확보함. 학습 데이터 라벨 생성은 오프라인 배치로 수행하며 실 서비스 추론 경로에는 포함되지 않음

배포 환경은 FastAPI와 비동기 작업 저장소(SQLite write-through)로 구성하여 서버 재시작 시에도 작업 이력이 보존되며, A2A 전송층은 Task lifecycle(submitted → working → input-required → completed)을 표준대로 노출하고 동일 요청 ID 재시도에 대한 멱등성을 보장함. LLM 응답은 SSE(Server-Sent Events) 스트리밍으로 수신하여 생성 중 텍스트를 실시간 표시함. LLM 인증 정보가 부재한 경우 규칙 기반 결과로 대체하지 않고 즉시 실패하도록 설계하여, 오류 결과가 정상 결과로 위장되는 경로를 구조적으로 차단함

# 3. 개발 성과

## 3.1 개발 성과 요약

### 3.1.1 개발 목표

◦기업 자료(IR·웹·텍스트)만으로 회사의 상(像)을 구축하고, 유사도가 아닌 보완성으로 파트너 후보를 발굴한 뒤, 구매자 관점 10축으로 적합도를 판단하여 근거가 추적되는 제안 초안까지 생성하는 엔드투엔드 B2B 매칭 에이전트를 구현함. 모든 판단에 근거와 검증상태를 부착하여 사람이 검토·반박할 수 있는 형태로 제시하며, 발송·미팅 등 대외 행위는 항상 사람이 결정하는 구조를 유지함

### 3.1.2 주요기능 명세

① 프로필 분석(Represent) ② 보강 질문(Clarify) ③ 후보 발굴(Retrieve) ④ 웹 파트너 탐색(Scout) ⑤ 적합도 판단(Judge) ⑥ 제안 초안(Compose) ⑦ A2A 전송층 ⑧ 실시간 대화형 UI

### 3.1.3 시스템 구성도

// mermaid 구성도 이미지 삽입 (시스템구성도_mermaid.png)

전 단계가 A2A Task lifecycle로 표현되며, 우측 대화 패널에 실시간으로 표시됨

### 3.1.4 사전 구현 성과

실제 기업 자료(사업계획서 PDF)로 전체 파이프라인을 관통하는 엔드투엔드 동작을 확인함

| 단계 | 입력 | 결과 | 소요 |
|---|---|---|---|
| Represent | 사업계획서 PDF 16페이지(12,166자) | 프로필 + 상(像) 7항목 추출 | 88.9초 |
| Retrieve | 합성 상대상 → 풀 검색 | 상위 5개 기업 순위 산출 | 9.8초 |
| Judge | 후보 1건 | 10축 판정 + 결정 확정 | 154.7초* |

*판단 소요는 측정 조건에 유의 — 상기 수치는 자기일관성 표본 1회·프로필 사전 구축 조건의 최선값임. 단일 호출 실측 범위는 61~458초로 변동이 크며, 자기일관성 투표(표본 3회)를 적용하는 실전 구성에서는 후보 1건당 약 8~23분이 소요됨. 응답 시간 최적화는 2차 지원기간 핵심 과제임(3.1.5)

환각 부재를 원문 대조로 검증함. 추출된 사실(대기업 ESG 협업사·수상 이력·특허 출원·해외 수주회 실적 등)을 원문 16페이지와 1:1 대조한 결과 허위 생성 사실 0건을 확인하였으며, 자료에 없는 항목은 생성하지 않고 '질문필요'로 표시함. 인용 계약 검증은 실존하지 않는 근거 청크 인용 14건을 자동 검출·폐기하였고(유효 청크 9개와 대조), 최소 프로필 게이트는 미달 자료를 후속 단계로 진행시키지 않음

시스템 규모는 애플리케이션 코드 약 10,200줄, 테스트 28개 파일, 판단 축 10개, 결정 규칙 6개임

### 3.1.5 향후 계획 및 한계점 보완

확인된 한계와 대응 계획은 다음과 같음

| 한계(실측) | 원인 진단 | 2차 지원기간 계획 |
|---|---|---|
| 대형 풀에서 순위 변별력 저하 — 상위 20위 점수가 0.2167~0.2428로 포화(표준편차 0.0069) | 문자 bigram 중첩도의 분모가 min()으로 설정되어 긴 문서일수록 유리 | 공급/수요 축을 분리한 비대칭 매칭으로 전환 |
| 통제 어휘의 실데이터 커버리지 부족 — 풀 1,140개 중 부합 6개(0.5%) | 리서치 데이터는 표준산업분류명, LLM 출력은 홍보성 문구로 어휘 계층 불일치 | 도메인 태그 체계 도입 및 라벨링으로 보강 |
| 판단 소요 시간 — 표본 1회 조건에서도 150~458초, 자기일관성 표본 3회 구성 시 후보당 약 8~23분 | 10축 확장 이후 추론 길이 증가 + 동일 입력의 소요 편차(61~458초)가 커서 표본 수와 곱해짐 | 축별 병렬화·캐스케이드 확대, 경량 사전 필터, 표본 간 병렬 실행 |
| 사람이 검증한 판단 라벨 1건 | 평가셋 미구축 | 수요측 라벨 932건 확보(작업 지침 수립 완료), 골든셋 확장 |

한계를 은폐하지 않는 것을 설계 원칙으로 함. 상기 항목은 모두 자체 계측으로 발견·문서화한 것이며 외부 지적으로 드러난 것이 아님. 2차 지원기간에는 공급 태그(판매 품목)와 수요 태그(구매 동기)를 분리하고 공급→수요 방향으로만 매칭하는 비대칭 구조로 전환하며, 골든셋 기반 자동 평가와 전문가(사람) 검증을 병행하는 이중 검증 체계로 발전시킬 계획임

## 3.2 주요 기능 명세 설명

기능 8종 중 시스템의 성격을 결정하는 3대 핵심(Represent·Retrieve·Judge)을 중심으로 기술함. 보강 질문·웹 탐색·제안 초안·A2A 전송층·대화형 UI는 3대 핵심을 보조하는 계층으로 말미에 요약함

### ① 프로필 분석(Represent) — 5층 독해와 정직성 계약 · 진척도 90%

기업 자료는 '결과'만 보여주고 '과정(전략·의도)'은 보여주지 않음 — 기업은 자사의 세일즈 전략을 외부에 공개하지 않기 때문임. 보이지 않는 것을 결과로부터 역추론하여 회사의 입체적 상(像)을 세우는 것이 전문 컨설턴트의 핵심 역량이었으며, 본 기능은 이를 다섯 겹의 독해 절차로 재현함. 1층(표면)은 자료의 문장 그대로 무엇을 만들고 판다고 말하는지, 2층(기능)은 누구의 어떤 결핍을 해소하며 고객이 실제로 비용을 지불하는 이유가 무엇인지, 3층(경제)은 누가 언제 무엇에 어떤 구조로 지불하는지(선투자 부담 주체·반복 매출 여부 포함), 4층(전략)은 트랙션·채용·레퍼런스 분포로부터 현 단계에서 무엇이 절실한지, 5층(양면)은 이 회사가 판매자이면서 동시에 구매자로서 무엇을 필요로 하는지를 독해함. 첫 레퍼런스가 급한 회사와 스케일이 급한 회사는 동일한 제안에 정반대로 반응하므로, 4층의 단계 판정이 이후 판단의 방향을 결정함

독해의 정직성은 프롬프트 지시가 아니라 계약으로 강제함. 모든 핵심 필드는 provenance(자료에 명시됨/자료에서 추론됨/자료로 알 수 없음)를 반드시 표기하고, 추론에는 확신도(0~1)를 병기하며, 알 수 없는 항목은 값을 비워 질문으로 전환함. 상(像) 7항목(정체성·수익구조·차별화·단계·자산·결핍·리스크 신호)은 각 항목을 "1문장째 판정, 2문장째 자료 원문 직접 인용, 3문장째 추정(있는 경우 「추정:」 표기와 함께 그 추정이 틀렸을 때 드러날 반증 신호 1개)"의 3문장 구조로 작성하도록 하고, 출력 전 자기검증 3문항(자료 인용이 없는 항목이 있는가, 정체성 문장이 타 회사에도 통용되는 범용 문장인가, 결핍과 단계 서술이 상호 모순인가)을 프롬프트에 내장함

프롬프트가 지키지 못한 것은 코드가 사후 방어함(이중 방어). 근거로 제시된 청크 ID의 실존 여부를 코드가 대조하여 환각 인용을 폐기·집계하고, 원문 3-gram 포함도가 임계 미만인 '확인됨' 필드를 '추론됨'으로 자동 강등하며, 회사명과 자사 행위 동사를 금칙어로 검사하여 고객의 문제를 기술해야 할 필드에 자사 소개가 기재되는 오류를 차단함. 정형 값도 코드가 최종 검증함 — 실측에서 "4년간 23배 성장" 문장으로부터 설립연도 4가 추출된 사례가 확인되어, 스키마 타입 검사만으로는 통과되는 오류를 값 범위 검증으로 차단함. 실측 결과 PDF 16페이지를 88.9초에 처리하였으며 원문 대조 환각 0건을 기록함

### ② 후보 발굴(Retrieve) — 보완성 검색과 분산 제어 · 진척도 70%

이상적 상대상을 합성하고 그 상으로 검색하는 2단 구조임. 1단은 요청 기업의 상과 의도로부터 "내 솔루션이 푸는 문제를 지금 겪고 있는 상대"를 한 문장으로 합성함 — 나의 동종업계가 아니라 나의 반대편을 그리는 것이며, 합성문에는 상대의 상황·고통의 관찰 가능한 신호·규모와 단계·지역이 담김. 프로필의 결핍(gaps)과 단계 서술(stage_narrative)을 합성 입력에 직접 전달하여 상(像)이 검색 씨앗으로 작동함

합성문은 확률적 단일 표본이나 그 문자열이 전체 후보의 점수에 반영되므로, 상류의 표본 하나가 랭킹 전체를 변동시키는 구조적 문제가 있음. 이에 프로필 필드에서 직접 도출되는 결정적 앵커 문장을 별도로 항상 계산하고, 검색 점수의 기저를 합성문과 앵커의 절반 혼합으로 구성하여 합성 요동이 점수에 미치는 분산을 1/4로 감쇠함(Var[(X+c)/2] = Var[X]/4). 동점 후보는 기업 ID 전순서로 고정하여 풀 적재 순서와 무관하게 재현 가능함

임계값은 캘리브레이션으로 확정함. 강한 후보 임계 τ=0.12는 실제 LLM 반복 실행에서 정상 매칭 점수대(0.176 이상)와 노이즈 점수대(0.070 이하) 사이의 공백 정중앙으로 설정한 값이며, 임계 근처 ±0.03 이내의 경계 후보는 재실행 시 순위가 뒤집힐 위험이 있음을 로그로 표시함. 앵커가 풀의 어느 후보와도 거의 겹치지 않는 경우(최대 중첩도 0.05 미만)는 프로필이 과소정의된 상태로 판정하여 검색 결과를 저신뢰로 표시하고 보강 질문을 권고함 — 임계 조정으로 해결할 수 없는 입력 품질 문제를 정직하게 알리는 장치임. 온톨로지 보정(지역 일치 +0.15, 산업 인접 +0.10)은 보완성 신호가 실재하는 경우(혼합 기저 0.10 이상)에만 가산함 — 보정이 신호를 만들어내면 조건이 맞지 않는 후보가 지역·산업만으로 상위에 오르기 때문임

재랭킹의 권한은 분할함. 실측에서 학습 스코어러(E9)와 API 재랭커가 상호 독립임에도 골든셋의 동일 케이스에서 동일하게 실패(top1 1.000→0.400)하는 현상을 관측하였음. 두 모델이 동일 지점에서 실패하는 것은 모델 품질이 아닌 구조의 문제이며, 원인은 양측 모두 질의·후보 텍스트만 참조하고 의도 제약(지역 지정·경쟁사 여부)을 참조하지 못하는 데 있음. 휴리스틱은 그 제약을 지역 가산과 경쟁사 강등으로 순위에 반영해 두는데, 재랭커가 의도를 모르는 유사도로 그 순위를 전체 덮어쓰는 것임. 이에 재랭커를 제거하는 대신 권한을 분할함 — 의도 충족 여부는 코드가 정렬 키 최상위(의도 티어)에서 결정하고, 재랭커는 동일 티어 내부의 순서만 결정함. 또한 재랭킹은 휴리스틱 점수의 상대 분산이 0.15 미만으로 밀집한 경우에만 발동하도록 조건화함 — 휴리스틱이 변별력을 확보한 경우(실측 정상 케이스 상대 분산 0.423)에는 개입하지 않고, 점수가 밀집하여 휴리스틱에 의견이 없는 경우(실측 오염 케이스 0.079)에만 동점 해소를 위임함. 이 조건화로 무조건 발동 시 0.400으로 하락하던 골든셋 top1을 1.000으로 복원하였으며, 최종 top1 정확도 0.960(5케이스 × 5회 반복)을 기록함

### ③ 적합도 판단(Judge) — 10축 판정과 3중 결정 게이트 · 진척도 80%

구매자 관점 10축(목적 정합·가치 서열·대체재 우위·기회비용·실증 신호·실행 게이트·단계 타이밍·신뢰·결정 구조·계약 보호)으로 판정함. 축 정의는 실제 B2B 협상 케이스에서 추출한 온톨로지를 정규 소스로 관리하며, 각 축은 핵심가치·판정 기준·구매자 유형별 목적·실제 협상에서 사용된 질문 문장을 보유함. 프롬프트와 스키마 열거형이 동일 파일 하나를 참조하도록 구성하여, 축 정의를 프롬프트에 복제할 때 발생하는 정의 불일치를 원천 차단함. 구매자 유형별 목적 분기를 두어 동일 제안이라도 브랜드(최종소비자 판매력)·CSR 조직(ESG KPI)·공공(정책 실적)·유통(재판매 가능성과 마진)의 상이한 구매 동기 기준으로 판정하며, 유형이 확정되지 않는 경우 미검증으로 처리함

모델의 판정 위에 3중 결정 게이트를 코드로 적층함. 첫째, 근거 게이트 — 실측에서 5개 축이 전부 '주의'임에도 모델이 "전략적 잠재력"을 이유로 추천을 산출한 사례를 확인함. 판단은 축 근거의 집계라는 계약상 적합 축이 하나도 없으면 추천은 성립할 수 없으므로, 이 경우 코드가 추천을 조건부 진행으로 하향함. 다만 근거 부족은 부적합 판정이 아니므로 유보·종료로 과교정하지 않음(정보 부재 ≠ 부적합). 둘째, 결정 게이트 — 축 상태로부터 최종 결정을 우선순위 6규칙으로 코드가 유도함(2.1 표 참조). 셋째, 일관성 게이트 — 판단을 복수 표본으로 반복 실행하여 범주형 결정을 다수결로 확정하고, 표본 간 일치율로부터 신뢰 대역을 결정적으로 도출함(모델의 자가보고 신뢰도는 보정되지 않은 값이므로 사용하지 않음). 일치율이 임계 미만이면 사람 검토 필수로 표시하고 자동 추천을 보류로 하향함 — 저합의 추천이 사람 검토 없이 나가는 경로를 결정적으로 차단하는 장치임

실측 결과 10축 전체 판정·결정 conditional을 기록하였으며, 별도 케이스에서는 부적합 축 누적으로 구조적 종료가 정확히 발동함(원본 데이터상 부적합으로 표기된 케이스와 일치). 소요 시간은 측정 조건에 따라 큰 폭으로 변동함 — 자기일관성 표본 1회·프로필 사전 구축 조건에서 154.7초였으나, 단일 호출의 실측 범위가 61~458초이고 표본 3회 구성에서는 그 배수가 되므로, 실전 구성의 후보당 소요는 약 8~23분임. 이는 국산 모델 추론 시간의 비결정성(5.4 개선 의견 참조)과 표본 수가 곱해지는 구조적 문제로, 표본 간 병렬 실행과 축별 병렬화가 2차 지원기간의 핵심 과제임

### ④ 보조 계층 — Clarify·Scout·Compose·A2A·UI

보강 질문(Clarify)은 자료로 확인할 수 없는 항목만 질의함. 질문은 5조건 계약(원자성 — 질문 1개당 미지 사실 1개, 판정가능성 — 답이 특정 필드를 확정할 것, 비중복성 — 기존 자료에서 도출 가능한 답은 묻지 않을 것, 정보가치 내림차순 정렬, 예산 최대 5개)을 전부 만족해야 출력되며, 조건을 만족하는 질문이 없으면 빈 목록을 반환함 — 채우기 위해 묻지 않음. 질문 형식도 폼 채우기가 아니라 컨설턴트의 질문("타겟 고객이 누구인가요"가 아니라 "지금까지 비용을 지불한 고객 중 가장 만족한 곳은 어디였고 무엇 때문에 지불했나요")을 지향함

웹 파트너 탐색(Scout)은 보유 풀에 적합한 상대가 없는 경우 자료의 명시 지식과 역추론된 상을 분리하여 가설을 수립하고 웹에서 후보를 충원함. 제안 초안(Compose)은 모든 주장이 판단의 어느 축·어느 근거에서 도출되었는지 매핑(claim_trace)을 강제하며, 발송은 항상 차단되어 사람이 결정함. A2A 전송층은 Task lifecycle 표준과 멱등성을 보장하고, 대화형 UI는 SSE 스트리밍으로 생성 중 텍스트를 실시간 표시하며 판단 결과를 두 에이전트의 왕복 대화로 재생함 — 상대 에이전트의 질문은 온톨로지에 보존된 실제 협상 질문 문장을 사용하고 신규 생성하지 않음

### 3.2.4 진척도

최종 목표 대비 현재까지의 개발 진척도는 다음과 같음 (전체 평균 약 79%)

|---|---|---|---|
| ① 프로필 분석(Represent) | 90% | −10% | 표 형식 자료의 정형 값 추출 미지원 — 실측 PDF에서 설립연도 1건 미추출(공란 처리로 오류는 없음). 기능 영향 소, 일정 리스크 낮음 |

| ③ 후보 발굴(Retrieve) | 70% | −30% | 대형 풀(1,140건)에서 상위 20위 점수 포화(표준편차 0.0069)로 변별력 상실 — 25건 데모 풀에서는 정상(top1 0.960)이나 실운영 규모 미해결. 비대칭 매칭 전환이 선결 과제이며 수요측 라벨링(932건)에 의존. 일정 리스크 **높음** |

| ⑤ 적합도 판단(Judge) | 80% | −20% | 판단 소요가 표본 1회 조건에서도 150~458초이며, 자기일관성 표본 3회의 실전 구성 시 후보당 약 8~23분 — 3분 예산 대비 크게 초과(축별·표본별 병렬화 미착수). 사람 검증 라벨 1건뿐 — 판정 로직은 완성이나 정확도 검증 미완. 일정 리스크 중 |

## 3.3 기술 우수성

### 3.3.1 정량적 우수성

스코어러 학습 통제 실험(H100 활용) 결과는 다음과 같음

| 실험 | 모델 | 데이터 구성 | seq | held-out ρ | 판정 |
|---|---|---|---|---|---|
| E5 | 1.2B | 실데이터 | — | 0.753 | 부분 학습 |
| E6 | **32B** | 실데이터 | — | **0.729** | 파라미터 증가 이득 없음 |
| E8 | 1.2B | 200사 | 2048 | 0.299 | 과적합·평균 붕괴 |
| E8c | 1.2B | 200사 | 4096 | 0.426 | 절단 회복, 여전히 미흡 |
| **E9** | **1.2B** | **1,000사** | **4096** | **0.789** | **채택** |
| E10 | 1.2B | 동일 데이터·라벨만 교체 | 4096 | 0.492 | 라벨 교체 실패 |

핵심 관찰은 네 가지임. 첫째, 32B가 1.2B를 상회하지 못함(0.729 vs 0.753/0.789) — 파라미터 규모가 아니라 데이터 구성과 시퀀스 길이가 성능을 결정함. 둘째, 시퀀스 길이 2048→4096에서 0.299→0.426으로 개선되어 입력 절단이 성능 저하의 실제 원인이었음을 확인함. 셋째, 데이터 200사→1,000사에서 0.426→0.789로 개선되어 데이터 규모가 지배적 변수임을 확인함. 넷째, 동일 데이터에서 라벨만 교체한 경우 0.789→0.492로 하락함 — 라벨 품질이 데이터 규모에 상응하는 중요 변수임

검색 정확도는 재랭킹 무조건 발동 시 골든셋 top1 0.400, 조건부 발동(현행) 시 0.960을 기록함(5케이스 × 5회 반복). 엔드투엔드 실행 시간은 프로필 분석 88.9초, 후보 발굴 9.8초, 적합도 판단 154.7초(표본 1회 조건, 실전 구성은 3.1.4 각주 참조)임. 정직성 지표로 원문 대조 환각 0건, 환각 인용 자동 폐기 14건, 최소 프로필 게이트의 미달 자료 통과 0건을 기록함

### 3.3.2 혁신성·도전성

판단 권한의 3층 분리. 본 시스템의 판단 구조는 "프롬프트가 지시하고, 모델이 판정하고, 코드가 결정한다"의 3층임. 프롬프트는 독해 절차와 정직성 규율을 지시하고, 모델은 축의 상태만 산출하며, 최종 결정·근거 검증·일관성 판정은 전부 결정론적 코드가 수행함. 프롬프트가 지키지 못한 규율은 코드가 사후 방어하는 이중 방어를 전 단계에 적용함 — 인용 실존 검증, 그라운딩 강등, 값 범위 검증, 근거 게이트, 결정 게이트, 일관성 게이트가 이에 해당함. 이 구조의 실익은 모델 교체 강건성임: 판단 정책이 코드에 있으므로 모델이 바뀌어도 정책이 유지되며, 이는 소버린 AI 환경에서 모델 선택지가 유동적인 국내 기업에 직접 이전 가능한 설계임

실패의 계측과 철회의 기록. 대리 지표가 개선되었음에도 실제 정확도가 하락하는 변경을 자체 계측으로 발견하여 철회한 사례를 코드 주석에 남김 — IDF 가중은 상위 점수 분산을 0.200→0.433으로 개선하였으나 골든셋 top1이 1.000→0.533으로 하락하여 기각하였고(분산은 대리 지표이며 코퍼스 크기에 따라 거동이 변하는 점수 함수는 그 자체로 취약하다는 결론), 조기 중단 가드는 실측에서 판단 1건을 386초로 증가시켜 철회하였으며, 재랭킹 무조건 발동은 top1을 0.400으로 붕괴시켜 조건부 발동으로 수정함. 실패 사례를 코드에 주석으로 보존하여 동일 시도가 반복되지 않도록 함

소버린 AI 운용 지식의 축적. 실 서비스 추론 전체를 국산 모델(K-EXAONE)로 구성하고, 운용 중 관측된 실패 유형(종료 토큰 오생성·저온 반복 고착·비결정적 빈 응답·추론 예산 소진)과 대응 방안을 실측 문서화함. 해당 기록 자체가 국산 모델을 실서비스에 적용하려는 국내 팀에 이전 가능한 자산임

### 3.3.3 대표 성과·실적

실제 B2B 협상 케이스에서 추출·체계화한 판단 온톨로지(BB1~BB10)와 결정 게이트 규칙, EXAONE 파인튜닝 실험 체계 E5~E11의 통제 변인별 비교 기록, A2A 프로토콜 준수 구현(Task lifecycle·멱등성·재시작 생존), 골든셋 기반 자동 채점과 반복 실행의 안정성 동시 측정이 가능한 평가 벤치마크 하네스, 932건 대상 수요측 라벨링 가이드(유형 7종 정의·판단 불가 원칙·오류 사례)를 수립함

### 3.3.4 신뢰성·안전장치

기술적 안전장치는 3.2에 상술한 이중 방어 체계와 동일함 — 인용 실존 검증(환각 인용 폐기·집계), 그라운딩 강등, 주체 분리 검사, 값 범위 검증, 출력 정화(한자·가나·손상 문자 제거), 빈 응답 재시도와 절단 시 명시적 오류, 인증 정보 부재 시 즉시 실패

운영적 안전장치는 다음과 같음. 시스템은 초안까지만 생성하고 발송·미팅은 항상 사람이 결정함. 실명 기업에 '강한/약한 후보' 등 등급을 화면에 표시하지 않음 — 등급 표시는 시스템이 사람을 대신하여 결론을 내리는 것이며, 실명 기업에 부착되어 대외 노출될 경우 명예훼손·영업방해 소지가 있으므로 순위와 근거만 제시함. 소수점 점수는 근거가 아닌 권위로 수용될 우려가 있어 화면에 표시하지 않되 내부 순위 산정에는 사용함. 결격으로 종료된 매칭은 상대에게 노출하지 않으며, 판단 입력과 산출을 감사 로그로 기록하여 사후 검증이 가능함

국내 AI API(K-EXAONE)는 실 서비스 추론 전체(프로필 분석·후보 합성·10축 판단·초안 생성)에 적용함. controllable reasoning을 활용한 2단계 호출(깊은 추론 → 구조화)을 설계하고, 예산 축소 시 10축 중 8축이 얕은 판정으로 저하되는 현상을 실측하여 16,384토큰을 표준으로 명문화함. 실패 유형의 실측·대응(추론 예산 소진 시 폴백, 비결정적 빈 응답 재시도, 종료 토큰 오류 복구, 저온 반복 회피)을 국산 모델 운용 지식으로 축적함

해외 API는 오프라인 학습 데이터 라벨 생성에 한정하여 사용하였으며 실 서비스 추론 경로에는 포함되지 않음

## 5.4 국내 AI 모델 활용 시사점

강점은 다음과 같음. 첫째, controllable reasoning의 실용성 — 추론 ON/OFF를 호출 단위로 제어할 수 있어 "깊은 사고 → 형식화"의 2단계 설계가 가능하였으며, 스키마 준수율과 환각 억제에 동시 기여함. 이는 해외 모델에서 일반적으로 제공되지 않는 제어 지점임. 둘째, 1.2B 파인튜닝으로 실용 성능 확보 — 대형 모델 없이 재랭킹 과제에서 held-out ρ 0.789를 달성하여 온프레미스·폐쇄망 배포가 현실적 선택지가 됨. 셋째, 한국어 비즈니스 문맥 이해 — 사업계획서·IR 자료의 한국어 표현을 별도 전처리 없이 처리함

개선 의견(실측 기반)은 다음과 같음. 첫째, 긴 추론에서 종료 토큰을 오생성하여 자체 종료에 실패하고 동일 토큰을 반복하는 사례를 관측하였으며, 사후 정규식으로 복구하였으나 모델 측 개선이 요구됨. 둘째, 온도를 낮추는 경우(0.2) 사고 사슬이 반복에 고착되어 종료하지 못하는 빈도가 급증하였으며, 0.5로 완화하여 해결하였으나 결정성이 필요한 구조화 작업에서 저온을 사용할 수 없는 제약이 됨. 셋째, 프롬프트가 한국어 출력을 명시하여도 추론 과정이 영어로 진행되는 사례가 발생함. 넷째, 동일 입력·동일 파라미터에서 정상 종료이면서 본문 0자를 반환하는 비결정적 사례를 관측함(재시도로 회복). 다섯째, 동일 입력의 소요 시간이 61초에서 458초까지 변동하여 서비스 SLA 설계에 어려움이 있음

상기 실패 유형과 대응 방안을 재사용 가능한 형태로 기록함. 국산 모델의 실서비스 적용 시 발생하는 문제에 대한 구체적 사례 축적 자체가 생태계 자산이며, 특히 경량 모델 파인튜닝으로 대형 모델을 대체 가능한 과제 유형을 실측으로 특정한 것은 비용 제약이 있는 국내 기업의 AI 도입 경로에 직접 적용 가능함

## 6.1 시연 가능 여부

■ 시연 가능

로컬 환경에서 전체 파이프라인이 동작하며 실제 기업 자료로 엔드투엔드 실행을 확인함. 네트워크 의존 구간은 K-EXAONE API 호출뿐이며 사전 실행 결과 재생 모드를 병행 준비함

## 6.2 시연 예정 방식

노트북 시연(웹 UI, 로컬 서버 + K-EXAONE API 호출)으로 진행함. 좌측 파이프라인 DAG와 우측 에이전트 대화를 동시에 표시하여 처리 과정이 실시간으로 확인되도록 구성함

## 6.3 시연 시나리오 개요

| 단계 | 입력 | 처리 | 출력 |
|---|---|---|---|
| 1 | 기업 IR PDF 업로드 | 5층 독해 → 상(像) 구축 | 프로필 카드(확인됨/추론됨 구분) |
| 2 | (자료 부족 시) | 최소 프로필 게이트 작동 | 4지선다 보강 질문 → 사용자 응답 |
| 3 | 의도 설정 | 이상적 상대상 합성 → 보완성 검색 | 후보 순위 목록 |
| 4 | 후보 선택 | 10축 판단 + 결정 게이트 | 축별 판정·근거, 최종 결정 |
| 5 | — | A2A 왕복 재생 | 상대 에이전트와의 질의응답 대화 |
| 6 | 판단 통과 시 | 제안 초안 생성 | 메일 초안 + 발송 차단 안내 |

시연 핵심은 생성 중 텍스트의 실시간 표시(사고 과정의 가시화), 자료에 없는 것을 생성하지 않고 질문하는 설계, 판단의 에이전트 대화 표현(A2A 구조의 시각화), 등급이 아닌 근거 제시, 발송 직전 사람에게 결정권 이양(자동화 경계의 명시)임
