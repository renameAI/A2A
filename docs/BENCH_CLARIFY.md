# B6 — 대화형 검색 루프 (멀티턴·멀티쿼리 → top-10)

메신저가 곧 검색 인터페이스다: 모호함을 오프라인 라벨로 해소하지 않고,
모호함이 관측되는 순간 사용자에게 질문으로 되돌린다. 코퍼스는 수집된 후보
풀이고, 질의 개선의 재료는 임베딩이 아니라 사용자의 답이다.

## 흐름

```
/search (웨이브1)  →  top 후보 + 명확화 질문(관측된 갈림에서만)
     ↓ 사용자: 선택지 답 · 자유 조건 · 후보별 👍이런 곳 더/👋아니에요
/refine            →  답을 반영한 새 검색어 → 웨이브2 수집 → 풀 병합
     ↓                → 피드백 재랭킹 → 새 질문 (반복)
/refine done=True  →  풀에서 top-k 확정
```

## 방법론 근거

| 근거 | 가져온 것 |
|---|---|
| [AGENT-CQ](https://arxiv.org/pdf/2410.19692) (2024) | LLM 명확화 질문은 **facet에 조건화**될 때 검색 성능을 올린다. 우리 facet = 후보 온톨로지의 관측된 갈림 |
| [Qulac / ClariQ](https://arxiv.org/pdf/2311.06119) 계열 | 질문은 결과를 실제로 가르는 축에서 — 갈림 없으면 질문도 없다 |
| [부정 피드백 질문](https://arxiv.org/pdf/2107.05760) | '아니에요' 반응이 다음 질문·검색어의 재료 |
| Rocchio (고전 적합성 피드백) | 피드백 재랭킹의 구조. 온톨로지 축 토큰 위에서 α=0.08 가산·β=0.10 감산 (β>α — 부정이 더 확실한 신호) |

## 집행 규율 (코드가 강제 — clarify.validate_questions)

- 선택지는 **실제 후보 company_id를 인용**해야 한다. 인용이 깨지면 선택지
  폐기, 유효 선택지 2개 미만이면 질문 폐기 — 지어낸 질문은 사용자의 시간을
  라벨링 노동으로 바꾸는 것이다.
- 모든 선택지가 같은 후보 집합이면 가르는 질문이 아니다 — 폐기.
- 이미 물은 질문(asked 이력) 재생성 금지. 질문 최대 3개.
- 후보 3곳 미만이면 질문 안 함 — 갈림을 물을 이유가 없다.
- 피드백 재랭킹은 LLM이 아니라 코드가 계산한다(판정=모델, 결정=코드).
  '아니에요' 후보는 목록에서 제거 — 거른 것을 다시 보여주는 건 반응 무시다.

## 검증

결정적 속성 테스트 7건 (tests/test_clarify.py, CI 게이트): 유효 질문 생존 /
환각 인용 폐기 / 비분할 질문 폐기 / 중복 질문 차단 / 3개 상한 / 피드백 방향성
(가산<감산) / 무피드백·무온톨로지 = 정확히 0.

라이브 멀티턴 E2E (GPT-5.6 Luna, 실검색):
- 웨이브1 후보 2곳 → 질문 없음 (3곳 미만 규칙의 정직한 작동)
- refine(답 1 + 좋아요 1 + 아니에요 1) → 신규 3곳, 좋아요 유사 후보 +0.068,
  아니에요 후보 목록 제거 확인
- 웨이브2 질문이 관측된 갈림에서 생성: "일본 내 수입·공급 중심 vs 해외 고객용
  상품 개발 중심" — 실제 풀에 두 부류가 있었다
- done → 최종 top-k 확정

## 남은 한계

- 수렴 품질(웨이브 수 대비 top-10 정확도)은 실사용자 데이터 없이는 못 잰다 —
  현재 검증은 기계(질문 집행·피드백 방향·병합·확정)까지다. 사용 로그가 쌓이면
  '확정까지 웨이브 수'와 '확정 후보의 답장률'(B4 원장)이 수렴 지표가 된다.
- 자유 조건 입력은 다음 검색어에 반영되지만 must_have 하드 필터로는 아직 안
  간다 — "냉장 물류 필수" 같은 조건이 랭킹 힌트로만 작동.
- 웨이브당 비용: 검색어 생성 1콜 + Tavily 4콜 + 기업당 판독 1콜. 비용 캡이
  전 웨이브에 걸쳐 있어 폭주는 막힌다.
