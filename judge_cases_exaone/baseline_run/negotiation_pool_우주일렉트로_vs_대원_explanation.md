# 협상 결론 설명서

## 1. 결론 요약

**구매자 결정**: 조건부 승인(conditional) — PoC 제안은 구조적 게이트와 기회비용 측면에서 수용 가능하나, 성능 입증을 위한 실증 데이터와 검증 경로, IP 및 계약 보호 체계가 명확하지 않아 조건부 승인 필요함.  
**판매자 outcome**: PoC 합의(poc_agreed) — 구매자의 구조적 게이트 확인 요구를 부분적으로 충족하며 PoC 실행 가능성을 유지하되, 층간소음 성능 검증 경로는 필요 시 별도 마련 가능하다고 제시함.

---

## 2. 판단 경로 (라운드별)

- **라운드 1**: 구매자는 PoC 제안이 리스크 완화 측면에서 유리하나, 구조적 게이트(ISO/TS 16949, KS F 2221 인증, 생산 유연성, 계약 제약 없음) 확인을 요구함. → `BB6_execution_gate` 판정: `na` (기록 없음), `dealbreaker`: `false`  
- **라운드 2**: 판매자는 인증 보유 및 PoC 납품 가능성을 제시하나, 층간소음 성능 검증 경로 미제시 → `BB5_evidence` 판정: `caution`, `evidence`: "성능 입증을 '제안'했으나, 검증 경로 미제시로 'confirmed' 불가"  
- **라운드 3**: 구매자는 IP 소유권, NDA 순서, 법적 보호 장치 미제시로 인해 계약 보호 측면에서 갭 지적 → `BB10_contract_protection` 판정: `na`, `evidence`: "IP·NDA 순서·독점 범위·표준 절차 등 계약 보호 요소 미제시"  
- **라운드 4**: 판매자는 생산 캐파(연간 1,200만 개), 15일 이내 납품 가능성, NDA 체결 후 기술 데이터 접근 가능성을 제시 → `BB6_execution_gate` 판정: `confirmed`, `verdict`: `fit`, `evidence`: "ISO/TS 16949 인증 보유 및 베트남 CE 기반 안전 인증 충족으로 PoC 납품 가능함을 명시하여 구조적 선결 조건 충족 확인"  
- **라운드 5**: 구매자는 층간소음 성능 검증 경로 및 과거 유사 프로젝트 사례 미제시로 인해 신뢰 측면에서 갭 유지 → `BB5_evidence` 판정: `caution`, `evidence`: "성능 입증을 '제안'했으나, 검증 경로 미제시로 'confirmed' 불가"  
- **라운드 6**: 판매자는 층간소음 KS F 2221 인증은 현재 적용 대상이 아니나 필요 시 별도 검증 경로 마련 가능하다고 명시 → `SB6_execution_honesty` 판정: `confirmed`, `limits_disclosed`: ["층간소음 KS F 2221 인증은 현재 적용 대상 아님", "검증 경로는 필요 시 별도 마련 가능", "IP 소유권은 PoC 기간 동안 고객 소유로 이전하지 않음"]  
- **라운드 7**: 구매자는 최종적으로 PoC 제안이 1순위 구매이유(층간소음 저감 기술 확보, 기술 리스크 회피)에 직접 기여함을 확인 → `BB1_purpose_fit` 판정: `confirmed`, `verdict`: `fit`, `evidence`: "PoC 제안이 '층간소음 저감 기술 확보'와 '기술 리스크 회피'라는 1순위 구매이유에 직접 기여함"

## 3. 게이트 점검

- **BB6(실행 게이트)**: `confirmed`, `verdict`: `fit`, `dealbreaker`: `false`  
  → ISO/TS 16949 인증 보유 및 베트남 CE 기반 안전 인증 충족으로 PoC 납품 가능함을 명시하여 구조적 선결 조건 충족 확인됨.  
- **BB8(신뢰/착취)**: `assumed`, `verdict`: `caution`, `authenticity_gate`: `na`, `exploitation_detected`: `false`  
  → 공개 수상 실물 확인, 실계약 증빙 등 실재·검증 가능 신호 미제시로 인해 신뢰 측면에서 갭 존재하나, 착취적 신호는 감지되지 않음.  
- **SB9(선별)**: `confirmed`, `screening`: `caution`  
  → 구매자가 IP 소유권, NDA 순서, 법적 보호 장치를 구체적으로 요구하며 정보 보호 필요성 강조. 이는 착취적 신호는 아니나, 정보 보호에 대한 경계 신호로 `caution` 수준 유지.

## 4. 왜 이 결정인가 / 왜 다른 결정이 아닌가

**채택 결정의 결정적 근거**:  
- PoC 제안은 구매자의 1순위 구매이유(층간소음 저감 기술 확보, 기술 리스크 회피)에 직접 기여하며, 실패 시 손실이 낮아 기회비용 측면에서 `fit` 판정됨.  
- 구조적 게이트(BB6_execution_gate)는 인증 및 생산 유연성, 자원 제약 없음 등을 통해 `confirmed`, `fit`으로 확인됨.  
- 판매자가 PoC 실행 가능성에 대한 구체적 근거(생산 캐파, 납기 유연성, 기존 계약 영향 없음)를 제시하여 실행 가능성 입증.

**인접한 대안 결정 기각 이유**:  
- **conditional 대신 recommend/hold 기각 이유**:  
  - `recommend`는 충분한 신뢰 기반과 검증 경로 확보 시 가능하나, 현재 `BB5_evidence`, `BB8_trust`, `BB10_contract_protection`에서 `caution` 또는 `na` 상태로 신뢰 및 법적 보호 측면에서 갭 존재.  
  - `hold`는 PoC 제안 자체가 리스크 완화 및 기회비용 측면에서 긍정적이므로 지나치게 보수적임.  
  → 따라서 `conditional`이 타당한 중간 지점으로 채택됨.
