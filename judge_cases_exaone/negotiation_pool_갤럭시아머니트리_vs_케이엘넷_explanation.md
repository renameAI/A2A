# 협상 결론 설명서

## 1. 결론 요약

**구매자 결정**: 구매자는 판매자가 구조적 선결 조건(FI-AP, PCI-DSS, RTGS 인증)의 공식 포털 링크와 전환비용 분석을 제공하지 않아 내부 기술 검토 게이트에서 구조적 미달로 판단하며, PoC 검토를 차단한다. 그러나 판매자가 인증 링크 및 전환비용 분석 제공을 약속했고, 2024년 4분기 내 시스템 구축 데드라인과의 정합 가능성이 존재하므로, 조건 충족 시 재검토 가능성을 열어두며 **조건부 검토**를 결정한다.

**판매자 outcome**: 판매자는 구매자의 요구(공식 포털 링크, 전환비용 분석, 타임라인 제시)를 수용하고 제공하겠다고 약속했으나, 실제 제공 여부는 미확정 상태이다. 그러나 내부 규정상 허용되는 방식으로 증거를 선제 제공하겠다는 CTA는 검증 게이트 통과 가능성을 열어두며, **구조화된 거래**(deal_structured) 상태로 판단된다.

## 2. 판단 경로 (라운드별)

- **라운드 1**: 판매자가 PoC 및 소량 실증 검증을 제안했으나, 구매자의 1순위 목적인 ‘물류 EDI와 결제 인프라 연동을 통한 수출입 자동화 정산 효율화’와의 직접적 연결 고리가 명시되지 않아 정합도가 낮음(BB1_purpose_fit, caution). 
 → **발화 인용**: “PoC 단계에서 공식 인증 현황 링크와 소량 실증 검증을 선제 제공드릴 수 있습니다.” 
 → **판정 변화**: 정합도 낮음 → caution

- **라운드 2**: 판매자가 FI-AP, PCI-DSS, RTGS 인증 링크 제공을 언급했으나, KISA ISMS 인증, 전자금융업 등록 현황 등 구매자의 도메인 신뢰 화폐로 즉시 확인 가능한 공식 포털 링크 제공 여부가 명시되지 않음(BB5_evidence, unfit). 
 → **발화 인용**: “FI-AP 인증, PCI-DSS 준수, RTGS 대응 능력에 대한 공식 포털 링크와 PoC 검증 계획을 즉시 제공드리며…” 
 → **판정 변화**: 검증 경로 미제공 → unfit

- **라운드 3**: 구매자가 인증 링크 미제공 시 내부 게이트에서 구조적 미달로 판단될 수 있음을 경고하며, PoC 이전에 인증 링크 제공을 요구(BB6_execution_gate, dealbreaker: true). 
 → **발화 인용**: “링크 미제공 시 내부 기술 검토 게이트에서 즉각 차단될 수 있음을 알려드립니다.” 
 → **판정 변화**: 구조적 선결 조건 미충족 → dealbreaker: true

- **라운드 4**: 판매자가 인증 링크와 전환비용 분석 제공을 약속했으나, 구체적 링크나 분석 자료는 제공되지 않음. 구매자는 여전히 BB5_evidence에서 unfit, BB6_execution_gate에서 caution 유지. 
 → **발화 인용**: “FI-AP·PCI-DSS·RTGS 인증 현황과 전환비용 분석을 공식 포털 링크로 즉시 제공드리며…” 
 → **판정 변화**: 약속은 있으나 미제공 → unfit, caution

- **라운드 5–7**: 판매자가 반복적으로 인증 링크 및 전환비용 분석 제공을 약속했으나, 실제 제공은 없음. 구매자는 BB6_execution_gate에서 dealbreaker: true를 유지하며, BB5_evidence에서 unfit을 유지. 
 → **발화 인용**: “공식 포털 링크와 연동된 단계별 타임라인으로 즉시 제공드리며…” 
 → **판정 변화**: 약속 반복 → 미제공 지속 → dealbreaker 유지

- **최종 상태**(라운드 7): 판매자가 인증 링크 제공을 약속했으나 미제공, 전환비용 분석도 미제공. 구매자는 BB6_execution_gate에서 dealbreaker: true, BB5_evidence에서 unfit을 유지하나, 판매자의 약속과 내부 규정상 허용 방식 제시로 인해 재검토 가능성을 열어둠. 
 → **판정 변화**: 구조적 미달 상태 유지 → 조건부 검토 결정

## 3. 게이트 점검

### BB6(실행 게이트)
- **판정**: caution, dealbreaker: true 
- **근거**: 판매자가 FI-AP, PCI-DSS, RTGS 대응 능력에 대한 공식 포털 링크 제공을 약속했으나, 현재까지 제공되지 않음. 
- **영향**: 내부 기술 검토 게이트에서 구조적 미달로 판단될 수 있으며, PoC 검토 자체가 차단됨. 
- **결과**: dealbreaker 수준 미달 → PoC 검토 불가

### BB8(신뢰/착취)
- **판정**: na, authenticity_gate: na, exploitation_detected: false 
- **근거**: 판매자의 ‘검증된 실적’ 주장은 공개 수상 실물 확인, 실계약 증빙, 공식 인증 링크 등 검증 가능한 신호 없이 제시됨. 
- **영향**: authenticity_gate 미통과 → 신뢰 구축 실패. 그러나 착취적 신호는 없어 ‘caution’ 수준 유지. 
- **결과**: 신뢰 기반 부족 → 신뢰 화폐 미제공

### SB9(선호적)
- **판정**: caution, screening: caution 
- **근거**: 구매자가 ‘구조적 선결 조건’을 강조하며, 인증 미충족 시 내부 게이트에서 거부 가능성을 시사. 정보 제공 방식에 대한 엄격한 기준 제시는 ‘경계 신호’로 해석 가능. 
- **영향**: 판매자의 증거 패키징(SB3) 및 문턱설계(SB5)가 구매자의 요구와 정합되지 않아 검증 게이트 통과 가능성 낮음. 
- **결과**: 경계 신호 → 검증 게이트 통과 가능성 낮음

## 4. 왜 이 결정인가 / 왜 다른 결정이 아닌가

### 채택 결정: **조건부 검토**

- **결정적 근거**: 
 1. 판매자가 FI-AP, PCI-DSS, RTGS 인증의 공식 포털 링크 제공을 약속했으며, 
 2. 전환비용 분석 제공을 약속했고, 
 3. 내부 규정상 허용되는 방식으로 증거 제공을 약속함으로써 검증 게이트 통과 가능성을 열어둠. 
 4. 구매자의 2024년 4분기 내 시스템 구축 데드라인과의 정합 가능성 존재.

→ 이 조건들이 충족되면 재검토 가능하므로, 무조건적 거부보다는 **조건부 검토**가 타당.

### 기각된 대안: **무조건적 거부**(conditional 대신 recommend/hold)

- **기각 이유**: 
 - 판매자가 구조적 요건(인증 링크, 전환비용 분석) 제공을 약속했으며, 
 - 내부 규정상 허용되는 방식으로 증거 제공을 약속함으로써 검증 게이트 통과 가능성을 열어둠. 
 - 구매자의 데드라인과의 정합 가능성 존재 → 무조건적 거부는 기회비용 관점에서 비효율.

→ **conditional**(조건부 검토)가 **hold**(보류)보다 타당. 
→ **recommend**(권장)은 증거 부족으로 인해 불가.

## 5. 조건과 검증 계획

| 조건 | 확인 방법 | 다음 단계 진입 조건 |
|------|----------|------------------|
| FI-AP, PCI-DSS, RTGS 인증의 공식 포털 링크 제공 | 링크 접속 후 인증 유효성, 발급 기관, 만료일 확인 | 모든 인증 링크 유효하고, 프로젝트 타임라인과 연계된 타임라인 제공 시 |
| 전환비용 분석 자료 제공 | 비용 항목(개발비, 인력, 유지보수, 전환 중단 리스크 등) 비교 분석 포함 여부 확인 | 기존 대안(자체개발, 경쟁사 PG 연동, 현상유지) 대비 전환비용 우위 입증 시 |
| 인증 현황이 프로젝트 타임라인(2024년 4분기 내 구축)과 연계된 구체적 마일스톤 제시 | 인증 완료 시점별 적용 일정, 연동 시스템 구축 일정과의 정합성 검토 | 인증 완료 시점이 2024년 4분기 내 구축 일정과 정합될 경우 |

→ 위 세 조건이 모두 충족되면 PoC 검토 검증 게이트 통과 가능.

## 6. 남은 가설

| 가설 | 채점 방법 (evidence_needed) |
|------|--------------------------|
| **exploit**: 판매자가 인증 링크를 제공하면 내부 게이트 통과 가능 | evidence_needed: FI-AP, PCI-DSS, RTGS 인증의 공식 포털 링크 제공 여부 |
| **explore**: 전환비용 분석 제공 시 기존 대안 대비 전환비용 우위 입증 가능 | evidence_needed: 기존 대안(자체개발, 경쟁사 PG 연동, 현상유지) 대비 전환비용 비교 분석 자료 |
| **explore**: PoC 검증 이전에 인증 현황이 프로젝트 타임라인과 연계된 구체적 마일스톤 제시 시 | evidence_needed: 인증 완료 시점별 적용 일정, 연동 시스템 구축 일정과의 정합성 검토 자료 |

→ 현재 **exploit 가설**은 미충족, **explore 가설**은 증거 미제공 상태로, 증거 확보 시 재검토 가능.
